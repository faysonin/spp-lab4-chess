# Лабораторная работа №4 — Шахматы онлайн

Многопользовательские шахматы в реальном времени. Клиент — чистый HTML/CSS/JS.
Сервер — Node.js (`http` + `ws`), без Express и Socket.IO. Партии пишутся в JSON
и переживают перезапуск.

## Запуск локально

```bash
cd "СПП/ЛР4"
npm install
npm start
```

Откройте [http://localhost:3000](http://localhost:3000) в двух вкладках (лучше
вторая — режим инкогнито, чтобы это был другой игрок). Создайте комнату,
вторым ником войдите по коду.

`PORT` и `HOST` берутся из окружения. На HTTPS клиент сам использует `wss:`.

## Протокол WebSocket

| Клиент | Поля | Сервер |
|--------|------|--------|
| `join` | `nickname`, `roomCode`, `seat` (`w`/`b`/пусто), `playerId?` | `welcome` + полный `snapshot` |
| `move` | `from`, `to` (`e2`/`e4`), `expectedMoveNumber`, `requestId` | `moved` всем в комнате |
| `resign` | — | `state` |
| `ping` / `leave` | — | `pong` / обновление состава |

Два места за доской (белые/чёрные), остальные — наблюдатели и видят ходы вживую.

## Конфликты

У партии есть `moveNumber` (номер полухода). Клиент отправляет тот, который видит.
Если на сервере номер уже другой — ответ `conflict` и текст **«Конфликт: ход уже сделан»**,
клиент рисует серверную доску. Первый корректный ход в этом ply принимается.
Чужой ход / ход не своей фигурой / ход в шах — ошибка, не перезапись.

## Офлайн

Статус «Онлайн / Переподключение / Нет сети». Последний неудавшийся ход лежит в
`localStorage` (`ch_pending`) и уходит после `welcome`. Ник, комната и `playerId`
восстанавливаются (`ch_session`). Пауза реконнекта 0,5 с … 10 с.

## Сохранение

`data/game.json` — комнаты, доска, права рокировки, очередь взятия на проходе,
места за столом, история ходов. Пустая комната не удаляется.

## Фигуры

SVG в `public/pieces/` — набор Colin M.L. Burnett (Wikimedia), CC BY-SA 3.0,
см. `public/pieces/SOURCE.txt`. Доска — дерево, координаты a–h и 1–8,
подсветка выбранной клетки, последнего хода и точек легальных ходов.

## Деплой

Готово к хостингу: `Procfile`, `render.yaml`, `fly.toml`, `GET /health`.

**Live URL (сейчас):** https://font-eyes-deals-eight.trycloudflare.com

Это Cloudflare Quick Tunnel к локальному `npm start` на этом компьютере.
Работает, пока запущены сервер и `cloudflared`. После перезапуска URL сменится.
Стабильный хостинг без туннеля — Render (бесплатно):

1. Залить репозиторий с корневой папкой `СПП/ЛР4` на GitHub.
2. [dashboard.render.com](https://dashboard.render.com) → New Web Service.
3. Build: `npm install`, Start: `npm start`.
4. Открыть `https://<имя>.onrender.com`.

## Защита (коротко)

1. Синхронизация — WebSocket, не polling.
2. Конфликт — отказ по `moveNumber`, клиент подчиняется серверу.
3. Правила (шах/мат/пат, рокировка, en passant, ферзь при превращении) считаются
   на сервере; клиент только подсвечивает ходы тем же модулем `public/js/rules.js`.
4. Наблюдатели получают те же `moved`, но ходить не могут.
